1) Objetivo da aula

Fazer o aluno entender que lógica proposicional não é apenas teoria: é uma linguagem para descrever decisões, validar regras e construir programas confiáveis.

Competências da aula: reconhecer proposições, usar conectivos, transformar frases em fórmulas e implementar essas regras em Python com and, or, not.

2) De onde vem a lógica?

2.1 Origem filosófica

A lógica nasce com a tentativa de organizar o raciocínio humano. Na Grécia Antiga, Aristóteles sistematizou formas de argumentação corretas (silogismos), buscando separar opinião de conclusão válida.

2.2 Da filosofia para a matemática

No século XIX, George Boole mostrou que raciocínios poderiam ser representados por uma álgebra com dois valores: verdadeiro e falso. Essa ideia foi um divisor de águas, porque transformou argumentos em operações.

Em resumo: a lógica começou para organizar o pensamento e virou um sistema formal que máquinas conseguem executar.

3) Como a lógica virou computação

3.1 A ponte com circuitos

Claude Shannon demonstrou que a álgebra booleana modela circuitos elétricos. Portas lógicas implementam fisicamente operações como AND, OR e NOT.

3.2 Do hardware ao software

  • No hardware: transistores formam portas lógicas.
  • No software: linguagens de programação aplicam as mesmas operações em regras.
  • No dia a dia: qualquer decisão condicional em código é lógica proposicional em ação.
# A mesma ideia em software
sensor_porta = True
alarme_ativado = True

acionar_sirene = sensor_porta and alarme_ativado
print("Sirene:", acionar_sirene)

5) Conceitos essenciais

5.1 Proposição

Frase declarativa com valor lógico verdadeiro ou falso.

  • Proposição: "10 é maior que 3".
  • Não proposição: "Feche a porta".

5.2 Conectivos e leitura

Conectivo Símbolo Python Leitura
Conjunção P ^ Q p and q P e Q
Disjunção P v Q p or q P ou Q
Negação ~P not p Não P
Condicional P -> Q (not p) or q Se P, então Q
Bicondicional P <-> Q p == q P se e somente se Q

5.3 Precedência

Sem parênteses, o Python avalia nesta ordem: not -> and -> or.

Regra prática: em expressão composta, use parênteses para tornar a intenção explícita.

6) Tradução para Python

6.1 Regra simples

tem_login = True
senha_correta = True

acesso = tem_login and senha_correta
print(acesso)  # True

6.2 Condicional lógica como fórmula

# P -> Q
p = True
q = False
print((not p) or q)  # False

6.3 Bicondicional

p = False
q = False
print(p == q)  # True

6.4 Mini tabela verdade automática

valores = [True, False]
for p in valores:
    for q in valores:
        print(p, q, "->", (not p) or q)

7) Exemplos lúdicos e comentados

7.1 Mundo do jogo

Um personagem pode abrir o baú se tiver chave e energia acima de 30.

tem_chave = True
energia = 25

abrir_bau = tem_chave and energia > 30
print("Pode abrir o baú?", abrir_bau)

7.2 Dia de praia

A turma vai para praia se for sábado e não estiver chovendo.

eh_sabado = True
chovendo = False

ir_praia = eh_sabado and (not chovendo)
print("Ir à praia?", ir_praia)

7.3 Controle de laboratório

Entrada liberada para monitor ou aluno com matrícula ativa e documento.

eh_monitor = False
matricula_ativa = True
tem_documento = True

liberado = eh_monitor or (matricula_ativa and tem_documento)
print("Entrada liberada?", liberado)

7.4 Funções para reutilizar regra

def implicacao(p, q):
    return (not p) or q

def bicondicional(p, q):
    return p == q

print(implicacao(True, False))
print(bicondicional(True, True))

7.5 Verificação de equivalência (De Morgan)

p = True
q = False

a = not (p and q)
b = (not p) or (not q)

print(a, b, a == b)  # True True True
Dinâmica em sala: cada grupo traduz primeiro em português, depois para símbolos e só então codifica em Python.

9) Erros comuns

  • Confundir = com ==.
  • Esquecer parênteses em regra composta.
  • Interpretar P -> Q como se exigisse P verdadeiro para funcionar.
  • Não testar cenários com True e False antes de validar a regra.

10) Lista de 20 exercícios (2 últimos horários)

Estes exercícios são para prática em sala. Sem entrega formal final.

3º horário (Exercícios 1 a 10) - Prática guiada

  1. Crie p e q booleanos e imprima p and q.
  2. Imprima p or q.
  3. Imprima not p.
  4. Com p=True, q=False, r=True, calcule (p and q) or r.
  5. Calcule not (p and q).
  6. Implemente p -> q usando (not p) or q.
  7. Implemente p <-> q usando p == q.
  8. Leia dois números e mostre se ambos são positivos.
  9. Leia idade e retorne True se estiver entre 18 e 60.
  10. Leia usuário/senha e valide acesso.

4º horário (Exercícios 11 a 20) - Prática aplicada

  1. Regra de desconto: VIP ou compra maior que 200.
  2. Regra de laboratório: crachá ativo e horário válido.
  3. Aprovação: nota >= 7 e frequência >= 75.
  4. Recuperação: 5 <= nota < 7 e frequência >= 75.
  5. Exiba p and q, p or q e not p na mesma linha.
  6. Leia três booleanos e avalie (p and q) or (not r).
  7. Modele: "Se estudou então passa".
  8. Modele: "Sistema online se e somente se servidor e rede ativos".
  9. Gere mini tabela verdade de p -> q.
  10. Regra de empréstimo: (renda >= 3000 e nome limpo) ou fiador válido.
Fechamento sugerido: 15 minutos finais com socialização das soluções e comparação de estratégias.
