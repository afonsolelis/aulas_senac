Dublês de teste e chamadas de API seguras

Objetivo da aula

Sair da aula com o cadastro de alunos e professores do organizacao-recursos buscando o endereço na ViaCEP, testado só com dublês, sem nenhum teste da suíte padrão acessando a internet, e com o cadastro funcionando mesmo quando a ViaCEP falha.

Como na Aula 10, o primeiro bloco acontece em laboratórios simulados do VS Code no repositório biblioteca-campus: o opencode gera o código a partir de um prompt e o professor confere com testes e git diff. Em quatro dos oito laboratórios o agente errou, e a revisão pegou o erro antes do commit. O segundo bloco é laboratório individual com os três prompts desta página.

1. O problema da dependência externa

O Trabalho 2 pede o endereço de alunos e professores pela ViaCEP (https://viacep.com.br/ws/{cep}/json/). O serviço é gratuito e não pede chave, mas está fora do seu controle. Quatro situações acontecem na prática: o serviço fica fora do ar ou a rede do CI não tem saída; a resposta demora e prende a requisição do usuário; o CEP não existe e a resposta é 200 com {"erro": "true"}; um campo muda de nome e o código passa a ler undefined.

Um teste de unidade que chama a ViaCEP de verdade fica lento, falha sem rede e não reproduz o timeout nem o CEP inexistente quando você quer. Por isso a suíte padrão troca a ViaCEP por dublês, e uma conferência separada e opcional verifica de tempos em tempos se o serviço real continua no formato que os dublês imitam.

2. Os cinco dublês de teste

A classificação é de Gerard Meszaros, no livro xUnit Test Patterns. No dia a dia todos viram "mock", mas o nome certo diz o que o teste confere: o resultado produzido (stub, fake) ou a interação com a dependência (spy, mock). O node:test traz o necessário em mock, sem biblioteca extra.

DublêO que fazNo node:test
DummyPreenche um parâmetro que o caminho testado nunca usaum objeto vazio, como logger: {}
StubDevolve uma resposta prontamock.fn(async () => ENDERECO)
SpyRegistra chamadas e argumentos para o teste conferir depoisfn.mock.callCount(), fn.mock.calls[0].arguments, mock.method(obj, 'warn')
MockCarrega a expectativa e falha na chamada erradamock.fn com assert dentro da implementação; t.mock.timers para o relógio
FakeImplementação real e simplificadaum objeto próprio, como o repositório em memória

Dummy e stub

test('stub: devolve um endereço pronto e o cadastro guarda', async () => {
  const buscarEndereco = mock.fn(async () => ENDERECO);   // stub
  const loggerDummy = {};                                 // dummy: este caminho não loga
  const cadastrar = criarCadastro({ repositorio: repositorioEmMemoria(), buscarEndereco, logger: loggerDummy });
  const aluno = await cadastrar({ nome: 'Ana', email: 'ana@campus.br', cep: '01001-000' });
  assert.equal(aluno.endereco.cidade, 'São Paulo');
  assert.equal(aluno.endereco_pendente, false);
});

Se o caminho testado passar a usar o logger, o dummy quebra com TypeError: logger.warn is not a function. O erro avisa que o parâmetro deixou de ser irrelevante; naquele caminho ele precisa ser um stub ou um spy.

Spy

test('spy: fetch chamado uma vez, com a URL e um AbortSignal', async (t) => {
  const fetch = mock.fn(async () => Response.json(viacepSe));
  await buscarEndereco('01001-000', { fetch });
  const [url, opcoes] = fetch.mock.calls[0].arguments;
  t.diagnostic('chamadas: ' + fetch.mock.callCount());
  assert.equal(fetch.mock.callCount(), 1);
  assert.equal(url, 'https://viacep.com.br/ws/01001000/json/');
  assert.ok(opcoes.signal instanceof AbortSignal);
});

test('spy: CEP com 7 dígitos não chega à rede', async () => {
  const fetch = mock.fn();
  await assert.rejects(buscarEndereco('0100100', { fetch }), { name: 'CepInvalidoError' });
  assert.equal(fetch.mock.callCount(), 0);
});

A afirmação "CEP inválido não chega à rede" só se prova com um spy que registra zero chamadas. No laboratório, ao remover a validação, o fetch foi chamado com /ws/0100100/json/ e o teste reprovou.

Mock e relógio controlado

const repositorio = {
  // a expectativa mora no próprio dublê: chamada errada falha aqui dentro
  salvarAluno: mock.fn(async (aluno, endereco) => {
    assert.equal(aluno.cep, '01001000');
    assert.equal(endereco, null);

test('mock.timers: 30 dias de atraso param no teto de 3000', (t) => {
  t.mock.timers.enable({ apis: ['Date'], now: new Date('2027-05-26T12:00:00-03:00') });
  assert.equal(multaNaDevolucao('2027-04-26'), 3000);
});

No laboratório, o agente escreveu um teste de multa que dependia da data de hoje. Ele passou no dia 26 e falhou no dia 30 com 1350 !== 750. O relógio também é uma dependência: com t.mock.timers.enable({ apis: ['Date'], now }), new Date() devolve a data fixada pelo teste, e o teto de 3000 centavos é testado sem esperar 30 dias.

Fake

export function repositorioEmMemoria() {
  const alunos = new Map();
  let proximoId = 1;
  return {
    async salvarAluno(aluno, endereco) {
      for (const existente of alunos.values()) {
        if (existente.email === aluno.email) {
          throw Object.assign(new Error('email repetido'), { code: '23505', constraint: 'alunos_email_unico' });
        }
      }
      const salvo = { id: proximoId++, ...aluno, endereco, endereco_pendente: endereco === null };
      alunos.set(salvo.id, salvo);
      return salvo;
    },
    async buscarAluno(id) { return alunos.get(id) ?? null; }

}

O fake só vale se se comportar como o repositório real. Na Aula 10, um fake escondeu o = NULL do SQL. Para evitar isso, a mesma suíte (test/compartilhado/contrato-repositorio.js) roda no fake, dentro de test/unidade, e no repositório pg, dentro de test/integracao. No laboratório, os mesmos três testes levaram 50 ms no fake e 4,3 s no banco real.

4. Uma chamada de API segura

  1. Validar antes de chamar: remover hífen e espaços e exigir 8 dígitos. CEP inválido vira 400.
  2. Limitar o tempo com AbortSignal.timeout(3000). Sem isso, o fetch espera o tempo que a rede quiser.
  3. Classificar a falha: CepInvalidoError (400), CepNaoEncontradoError (422) e ViaCepIndisponivelError para timeout, erro de rede e status fora de 2xx, guardando a causa original em cause.
  4. Degradar sem perder o cadastro: com a ViaCEP indisponível, o aluno é salvo com o endereço pendente, o logger registra o CEP e a resposta continua 201. CEP inexistente é diferente: o dado do usuário está errado, e a resposta é 422.
  5. Injetar a dependência: buscarEndereco(cep, { fetch }) usa globalThis.fetch em produção e recebe um mock.fn no teste.
// src/servicos/viacep.js
export class CepInvalidoError extends Error { name = 'CepInvalidoError'; }
export class CepNaoEncontradoError extends Error { name = 'CepNaoEncontradoError'; }
export class ViaCepIndisponivelError extends Error { name = 'ViaCepIndisponivelError'; }

const URL_BASE = 'https://viacep.com.br/ws/';

export function normalizarCep(cep) {
  const digitos = String(cep ?? '').replace(/[\s-]/g, '');
  if (!/^\d{8}$/.test(digitos)) throw new CepInvalidoError('CEP deve ter 8 dígitos: ' + cep);
  return digitos;
}

export async function buscarEndereco(cep, { fetch = globalThis.fetch, timeoutMs = 3000 } = {}) {
  const limpo = normalizarCep(cep);
  let resposta;
  try {
    resposta = await fetch(URL_BASE + limpo + '/json/', { signal: AbortSignal.timeout(timeoutMs) });
  } catch (causa) {
    throw new ViaCepIndisponivelError('ViaCEP não respondeu', { cause: causa });
  }
  if (!resposta.ok) throw new ViaCepIndisponivelError('ViaCEP respondeu ' + resposta.status);
  const dados = await resposta.json();
  if (dados.erro === true || dados.erro === 'true') {
    throw new CepNaoEncontradoError('CEP não encontrado: ' + limpo);
  }
  return { cep: limpo, logradouro: dados.logradouro, bairro: dados.bairro, cidade: dados.localidade, uf: dados.uf };
}
// src/servicos/cadastro.js
export function criarCadastro({ repositorio, buscarEndereco, logger }) {
  return async function cadastrarAluno(dados) {
    const cep = normalizarCep(dados.cep);
    let endereco = null;
    try {
      endereco = await buscarEndereco(cep);
    } catch (erro) {
      if (!(erro instanceof ViaCepIndisponivelError)) throw erro;
      logger.warn('ViaCEP indisponível; cadastro com endereço pendente', { cep });
    }
    return repositorio.salvarAluno({ ...dados, cep }, endereco);
  };
}

No laboratório, o agente testou o timeout com um fetch que nunca respondia e esperou o AbortSignal de verdade. O teste passou em 3004 ms. Um teste de unidade lento costuma esconder uma dependência real; trocado por um stub que rejeita com new DOMException('timeout', 'TimeoutError'), o mesmo caminho é coberto em menos de 1 ms, e a suíte voltou para 58 ms.

5. Nenhum teste da suíte padrão chama a internet

Um helper troca o fetch global por um dublê que lança e anota a URL. O afterEach reprova o teste mesmo quando o código engoliu o erro.

// test/unidade/helpers/sem-rede.js
import { mock, afterEach } from 'node:test';
import assert from 'node:assert/strict';

export function proibirRede() {
  const rede = mock.method(globalThis, 'fetch', async (url) => {
    throw new Error('teste tentou acessar a rede: ' + url);
  });
  afterEach(() => {
    const urls = rede.mock.calls.map((c) => String(c.arguments[0]));
    rede.mock.resetCalls();
    assert.deepEqual(urls, [], 'teste acessou a rede: ' + urls.join(', '));
  });
  return rede;
}

No laboratório, o agente escreveu um teste da rota passando o buscarEndereco real "para o teste ficar mais realista". A rota respondeu 201, porque o cadastro tratou a falha como ViaCEP indisponível e salvou o endereço pendente. Só o guarda percebeu a chamada: teste acessou a rede: https://viacep.com.br/ws/01001000/json/. Sem ele, o teste passaria no Codespace e quebraria no CI sem rede, ou passaria sem testar o endereço.

6. POST /alunos com Express 5 e supertest

criarApp recebe as dependências e não chama listen; o supertest abre uma porta efêmera para cada requisição. No Express 5, a promessa rejeitada dentro da rota chega sozinha ao middleware de erro, que precisa ter quatro parâmetros. Só src/server.js monta o app com a ViaCEP real e o pool do PostgreSQL, e nenhum teste importa esse arquivo.

// src/app.js
export function criarApp({ repositorio, buscarEndereco, logger = console }) {
  const app = express();
  app.use(express.json());
  const cadastrar = criarCadastro({ repositorio, buscarEndereco, logger });

  app.post('/alunos', async (req, res) => {
    const aluno = await cadastrar(req.body);
    res.status(201).json(aluno);
  });

  app.use((erro, req, res, _next) => {
    if (erro instanceof CepInvalidoError) return res.status(400).json({ erro: erro.message });
    if (erro instanceof CepNaoEncontradoError) return res.status(422).json({ erro: erro.message });
    if (erro.code === '23505') return res.status(409).json({ erro: 'e-mail já cadastrado' });
    logger.error(erro);
    res.status(500).json({ erro: 'erro interno' });
  });
  return app;
}
// trecho de test/unidade/app.test.js
proibirRede();

test('201 com endereço pendente quando a ViaCEP cai', async () => {
  const { app, warn } = montar(mock.fn(async () => { throw new ViaCepIndisponivelError('timeout'); }));
  const res = await request(app).post('/alunos').send(ANA).expect(201);
  assert.equal(res.body.endereco_pendente, true);
  assert.equal(warn.mock.callCount(), 1);
  assert.deepEqual(warn.mock.calls[0].arguments[1], { cep: '01001000' });
});

test('400 para CEP com 7 dígitos, sem chamar a ViaCEP', async () => {
  const buscar = mock.fn(async () => ENDERECO);
  const { app } = montar(buscar);
  await request(app).post('/alunos').send({ ...ANA, cep: '0100100' }).expect(400);
  assert.equal(buscar.mock.callCount(), 0);
});

7. Teste de contrato leve

O contrato confere, contra a ViaCEP real, os nomes e os tipos dos campos que o sistema usa, e não os valores. Ele mora em test/contrato, fora de test/unidade e de test/integracao, e só chama a rede com CONTRATO=1; fora disso, aparece como pulado com o motivo.

const pular = process.env.CONTRATO !== '1' && 'defina CONTRATO=1 para chamar a ViaCEP de verdade';

test('ViaCEP devolve os campos que o sistema usa', { skip: pular }, async () => {
  const res = await fetch('https://viacep.com.br/ws/01001000/json/', { signal: AbortSignal.timeout(5000) });
  assert.equal(res.status, 200);
  const corpo = await res.json();
  for (const campo of ['cep', 'logradouro', 'bairro', 'localidade', 'uf']) {
    assert.equal(typeof corpo[campo], 'string', 'campo ' + campo);
  }
});
"test:contrato": "CONTRATO=1 node --test test/contrato"

O contrato roda num workflow próprio, .github/workflows/contrato.yml, com schedule semanal e workflow_dispatch, fora do CI de push. Se a ViaCEP renomear localidade, os testes de unidade continuam verdes com o fixture antigo; o contrato falha com campo localidade e avisa que o fixture e o código precisam mudar.

9. Como revisar o que o agente gerou

Nos laboratórios, o agente errou quatro vezes: usou um dummy num caminho que loga, escreveu um teste preso à data de hoje, esperou 3 s reais para testar o timeout e passou a ViaCEP real para um teste de rota. Em todos os casos, o resumo do agente dizia que os testes passavam. Antes de cada commit, confira:

  • npm test rodado por você, com o guarda de rede ativo e duration_ms baixo.
  • Para cada dublê, qual dos cinco ele é e o que o teste confere com ele.
  • No git diff, nenhuma URL real dentro de test/unidade e nenhum segredo em src/, test/ ou .github/.
  • Pedidos de permissão do agente lidos antes de aceitar.

10. Prompt 1 · cliente da ViaCEP e testes com dublês

30 min

No repositório organizacao-recursos, em JavaScript puro com ES modules, crie src/servicos/viacep.js exportando as classes CepInvalidoError, CepNaoEncontradoError e ViaCepIndisponivelError, a função normalizarCep(cep) e a função buscarEndereco(cep, { fetch = globalThis.fetch, timeoutMs = 3000 } = {}). buscarEndereco remove hífen e espaços e exige 8 dígitos; se não houver, lança CepInvalidoError sem chamar o fetch. Chama https://viacep.com.br/ws/{cep}/json/ com signal: AbortSignal.timeout(timeoutMs). Se a resposta tiver erro igual a "true" ou true, lança CepNaoEncontradoError. Timeout, falha de rede e status fora de 2xx viram ViaCepIndisponivelError com a causa original em cause. No sucesso, devolve { cep, logradouro, bairro, cidade, uf }. Escreva test/unidade/viacep.test.js com node:test e node:assert/strict usando só dublês: stub de fetch com mock.fn devolvendo Response.json com o JSON real de 01001000; stub para {"erro": "true"}; spy conferindo que o fetch foi chamado uma vez, com a URL certa e um AbortSignal; spy provando zero chamadas para CEP com 7 dígitos; stub que rejeita com new DOMException('timeout', 'TimeoutError') para o timeout. Nenhum teste pode acessar a internet nem esperar o timeout real. Ao terminar, rode npm test e mostre o duration_ms.
Antes de aceitar: o teste do CEP inválido confere fetch.mock.callCount() === 0, e a suíte inteira termina em menos de 1 s.

11. Prompt 2 · cadastro de alunos e professores com endereço

35 min

Crie src/app.js exportando criarApp({ repositorios, buscarEndereco, logger }) com Express 5 e as rotas POST /alunos e POST /professores. O corpo traz nome, email, cep e numero. CEP inválido responde 400; CEP inexistente responde 422; ViaCEP indisponível não impede o cadastro: grava com o endereço pendente (na tabela de CEPs ou na coluna que o seu docs/der.md definiu), chama logger.warn com o CEP e responde 201 com endereco nulo e endereco_pendente verdadeiro; sucesso responde 201 com o endereço. E-mail repetido (code 23505) responde 409. Use um middleware de erro com quatro parâmetros. Crie src/server.js, o único arquivo que monta o app com o buscarEndereco real e o pool de DATABASE_URL e chama listen. Instale supertest como devDependency. Crie test/unidade/fakes/repositorio-em-memoria.js com o mesmo comportamento do repositório pg, inclusive o erro com code 23505, e test/unidade/app.test.js com supertest, o fake e stubs de buscarEndereco feitos com mock.fn, cobrindo os cinco casos para alunos e o caso de sucesso para professores. Use mock.method(logger, 'warn') para conferir que a falha da ViaCEP foi registrada uma vez com o CEP.
Antes de aceitar: app.test.js não importa server.js nem pg, e todo criarApp do teste recebe um buscarEndereco que é mock.fn.

12. Prompt 3 · contrato opcional, guarda de rede e segredos

20 min

Crie test/unidade/helpers/sem-rede.js exportando proibirRede(), que usa mock.method(globalThis, 'fetch') para lançar erro com a URL pedida e registra um afterEach que falha se houve alguma chamada, listando as URLs. Chame proibirRede() no topo de todo arquivo de test/unidade que envolva HTTP. Crie test/contrato/viacep.contrato.test.js, que só chama a ViaCEP de verdade quando CONTRATO=1 e, fora disso, aparece como pulado com o motivo. Ele confere que a resposta de 01001000 tem cep, logradouro, bairro, localidade e uf como strings e que a de 99999999 é exatamente { erro: "true" }, com AbortSignal.timeout(5000). Mova o JSON de exemplo para test/fixtures/viacep-01001000.json e use o mesmo arquivo nos stubs. Acrescente o script "test:contrato": "CONTRATO=1 node --test test/contrato" e o workflow .github/workflows/contrato.yml com schedule semanal e workflow_dispatch, fora do CI de push. Por fim, liste qualquer chave, senha ou DATABASE_URL real encontrada em src/, test/ ou .github/; tudo deve vir de process.env ou de secrets.
Antes de aceitar: troque um stub de app.test.js pelo buscarEndereco real e rode npm test; o guarda precisa reprovar com a URL da ViaCEP. Desfaça com git restore.

13. Entregável e checagem

buscarEndereco com fetch injetado, POST /alunos e /professores com degradação testados por supertest, guarda de rede na suíte de unidade e contrato opcional da ViaCEP, tudo na main com o CI verde. Cada prompt vai numa branch curta (feat/viacep, feat/cadastro-endereco, test/contrato-viacep) integrada com git merge --ff-only. Se houver issue de feedback aberta da Aula 10, responda com um commit fix(escopo): o que mudou (#N) e Closes #N no corpo.

O que o professor confere na mesa

  • Você aponta, em cada teste, qual dos cinco dublês usou e por quê.
  • Com o stub de ViaCEP indisponível, o cadastro responde 201 com endereço pendente.
