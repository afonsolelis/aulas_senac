Fundamentos: O Que É Viabilidade de Pesquisa?

Definição Formal

Estudo de Viabilidade de Pesquisa é uma análise sistemática e quantitativa que determina se um projeto de TCC pode ser executado com sucesso, considerando os recursos disponíveis, conhecimento necessário, tempo disponível, infraestrutura e riscos inerentes ao caminho metodológico escolhido.

Por Que Fazer Estudo de Viabilidade?
  1. Evitar Frustrações: Descobrir limitações no início, não no TCC2
  2. Economia de Tempo: Redirecionar o projeto cedo se necessário
  3. Tomada de Decisão: Base objetiva para escolher caminho metodológico
  4. Justificativa Acadêmica: Demonstra planejamento rigoroso na monografia
  5. Credibilidade: Mostra que você pensou nos desafios
Consequências de Não Fazer
  • DSR: Descobrir que a API custa $500/mês ou hardware não suporta ML
  • Teórico: Perceber que a matemática está muito além do seu nível
  • Experimental: Não ter acesso ao laboratório ou equipamentos necessários
  • Survey: Descobrir que não tem acesso às bases de dados necessárias
  • Todos: Reprovar na banca por não entregar o prometido

Caminho 1: Viabilidade para DSR

Design Science Research - Criar POC, Protótipo ou MVP

1. Viabilidade Técnica (30 pts)
  • Tecnologia existe? Madura (10) / Beta (5) / Não existe (0)
  • Conhecimento: Domínio (10) / Parcial (5) / Zero (0)
  • Infraestrutura: Disponível (10) / Parcial (5) / Nada (0)
2. Viabilidade Econômica (20 pts)
  • Custo total: R$ 0 (20) / R$ 1-500 (15) / R$ 501-2k (10) / R$ 2k-5k (5) / >R$ 5k (0)
  • Incluir: APIs, cloud, licenças, hardware GPU, domínio
3. Viabilidade Temporal (30 pts)
  • Aprendizado: Sabe tudo (10) / 1-2 sem (5) / >1 mês (0)
  • Implementação: <2 meses (15) / 2-4m (10) / 4-6m (5) / >6m (0)
  • Buffer: 30%+ folga (5) / <30% (0)
4. Viabilidade Operacional (20 pts)
  • Usabilidade: Intuitivo (10) / Tutorial (5) / Complexo (0)
  • Integração: Standalone (10) / Simples (5) / Complexa (0)
Total: 100 pontos

80-100: VIÁVEL 60-79: ATENÇÃO < 60: INVIÁVEL

Caminho 2: Viabilidade para Pesquisa Teórica/Matemática

Desenvolvimento de provas, teoremas, formalizações matemáticas

1. Viabilidade Matemática (35 pts)
  • Nível matemático: Graduação (15) / Mestrado (10) / Doutorado (0)
  • Seu background: Domina tópico (10) / Estudou parcial (5) / Nunca viu (0)
  • Complexidade provas: Direta (10) / Moderada (5) / Alta (0)
2. Viabilidade Bibliográfica (25 pts)
  • Literatura disponível: Abundante (15) / Moderada (10) / Escassa (0)
  • Acesso material: Aberto (10) / Parcial paywall (5) / Tudo pago (0)
3. Viabilidade de Contribuição (20 pts)
  • Gap identificado: Claro (10) / Possível (5) / Inexistente (0)
  • Originalidade: Nova abordagem (10) / Extensão (5) / Revisão (0)
4. Viabilidade Temporal (20 pts)
  • Aprendizado: <1 mês (10) / 1-3m (5) / >3m (0)
  • Desenvolvimento: <4 meses (10) / 4-6m (5) / >6m (0)
Total: 100 pontos

80-100: VIÁVEL 60-79: ATENÇÃO < 60: INVIÁVEL

Exemplo inviável: "Provar P≠NP" - problema do milênio, nível doutorado+, gap inexistente (já muito estudado)

Caminho 3: Viabilidade para Pesquisa Experimental

Condução de experimentos, coleta de dados, análise estatística

1. Viabilidade de Infraestrutura (30 pts)
  • Acesso laboratório: Pleno (15) / Parcial (10) / Nenhum (0)
  • Equipamentos: Disponíveis (10) / Comprar barato (5) / Caros/indisponíveis (0)
  • Software necessário: Grátis (5) / Licença estudante (3) / Pago (0)
2. Viabilidade de Dados (25 pts)
  • Coleta de dados: Fácil (15) / Moderada (10) / Difícil (0)
  • Tamanho amostra: Suficiente (10) / Limítrofe (5) / Insuficiente (0)
3. Viabilidade Ética (25 pts)
  • Comitê Ética (CEP): Não precisa (15) / Precisa, simples (10) / Precisa, complexo (0)
  • LGPD/Privacidade: Sem dados pessoais (10) / Anonimizado (5) / Sensível (0)
4. Viabilidade Temporal (20 pts)
  • Setup: <1 mês (5) / 1-2m (3) / >2m (0)
  • Experimentos: <2 meses (10) / 2-4m (5) / >4m (0)
  • Análise: <1 mês (5) / 1-2m (3) / >2m (0)
Total: 100 pontos

80-100: VIÁVEL 60-79: ATENÇÃO < 60: INVIÁVEL

Exemplo inviável: "Experimento com ressonância magnética" - equipamento caríssimo, CEP complexo, sem acesso

Caminho 4: Viabilidade para Survey/Revisão Sistemática

Mapeamento sistemático, revisão bibliográfica estruturada (PRISMA)

1. Viabilidade de Acesso (30 pts)
  • Bases de dados: Acesso completo IEEE/ACM/Scopus (20) / Parcial (10) / Só Google Scholar (0)
  • VPN institucional: Funciona (10) / Instável (5) / Sem acesso (0)
2. Viabilidade de Escopo (25 pts)
  • Nº papers esperado: 50-300 (15) / 300-800 (10) / >800 ou <50 (0)
  • Tema definido: Questão clara (10) / Vaga (5) / Indefinida (0)
3. Viabilidade de Ferramentas (20 pts)
  • Gerenciador ref: Zotero/Mendeley (10) / Manual (0)
  • Screening: Rayyan/Parsifal (10) / Planilha (5) / Manual (0)
4. Viabilidade Temporal (25 pts)
  • Busca: <2 sem (5) / 2-4sem (3) / >1m (0)
  • Screening: <1 mês (10) / 1-2m (5) / >2m (0)
  • Extração/Análise: <2 meses (10) / 2-4m (5) / >4m (0)
Total: 100 pontos

80-100: VIÁVEL 60-79: ATENÇÃO < 60: INVIÁVEL

Dica: Faça busca piloto antes! 5.000+ papers = escopo muito amplo, <30 papers = escopo muito restrito

Como Aplicar a Avaliação de Viabilidade

Passo a Passo Geral
  1. Identificar caminho metodológico do seu TCC (DSR, Teórico, Experimental, Survey)
  2. Usar os critérios específicos do caminho escolhido (slides 4-7)
  3. Pontuar honestamente cada dimensão (sem otimismo excessivo!)
  4. Calcular total e analisar resultado
  5. Identificar riscos principais e planos de mitigação
  6. Documentar no TCC (seção Viabilidade da Pesquisa)
Erros Comuns a Evitar
  • Otimismo excessivo: "Vou aprender Haskell em 1 semana!" NÃO
  • Ignorar custos ocultos: APIs gratuitas têm limites de requisições
  • Subestimar complexidade matemática: Cálculo 4 é diferente de Álgebra Linear Avançada
  • Esquecer aprovação ética: CEP pode demorar 3+ meses
  • Não ter plano B: E se a API principal cair? E se não conseguir acesso ao lab?
Interpretando os Resultados

80-100 pts

VIÁVEL
Pode prosseguir com confiança

60-79 pts

ATENÇÃO
Ajustes necessários antes de continuar

< 60 pts

INVIÁVEL
Repensar escopo ou mudar de caminho

🎯 DESAFIO PRÁTICO

Avalie SEU Projeto de TCC

Use os critérios do caminho metodológico que você escolheu

DSR (Design Science Research)
O que avaliar:
  • Tecnologias necessárias e seu domínio
  • Custos de APIs, cloud, hardware
  • Tempo de aprendizado + implementação
  • Complexidade de integração
Perguntas-chave:
  • A stack tecnológica é madura e estável?
  • Você domina as tecnologias ou precisará aprender?
  • O orçamento disponível cobre todos os custos?
  • Há tempo suficiente para implementar + testar?
Pesquisa Teórica/Matemática
O que avaliar:
  • Nível matemático exigido vs. seu background
  • Literatura disponível e acessível
  • Existência de gap de pesquisa claro
  • Tempo para aprender conceitos + desenvolver provas
Perguntas-chave:
  • O nível matemático é de graduação ou pós?
  • Você tem a base matemática necessária?
  • Há papers suficientes acessíveis?
  • O gap de pesquisa está claro e é factível?
Pesquisa Experimental
O que avaliar:
  • Acesso a laboratório e equipamentos
  • Custo de materiais/equipamentos
  • Necessidade de aprovação CEP/ética
  • Tempo para setup + execução + análise
Perguntas-chave:
  • Você tem acesso ao lab/equipamentos necessários?
  • Precisa comprar algo? Quanto custa?
  • Envolve seres humanos? Precisa CEP?
  • A amostra será suficientemente grande?
Survey/Revisão Sistemática
O que avaliar:
  • Acesso a bases de dados (IEEE, ACM, Scopus)
  • Escopo: nº esperado de papers (50-800)
  • Ferramentas disponíveis (Zotero, Rayyan)
  • Tempo para busca + screening + análise
Perguntas-chave:
  • Você tem acesso às bases principais?
  • A busca piloto retorna 50-800 papers?
  • A questão de pesquisa está bem definida?
  • Há tempo para screening manual de centenas de papers?

O Que Entregar
