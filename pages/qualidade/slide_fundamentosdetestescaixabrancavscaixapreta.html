Introdução aos Testes de Software

O que são Testes?

Processo de verificar se o software atende aos requisitos especificados e se comporta conforme o esperado.

Duas Abordagens Principais

  • Caixa Branca: Foco na estrutura interna do código
  • Caixa Preta: Foco no comportamento externo

Teste Caixa Branca (White-Box)

Definição

O teste de Caixa Branca analisa a estrutura interna do código. O testador tem acesso completo ao código-fonte e conhece a implementação interna.

Objetivos

  • Verificar caminhos de execução do código
  • Testar condições, loops e branches
  • Validar lógica interna e estruturas de dados
  • Cobertura de código (statements, branches, paths)
"Enxergamos" o código

Conhecimento interno da implementação é essencial

Exemplo: Teste de Unidade com JUnit

Testando a lógica interna de um método de cálculo

@SpringBootTest public class CalculadoraTest { @Autowired private Calculadora calculadora; @Test void testarSoma() { // Arrange - conhecemos a estrutura interna int a = 5, b = 3; // Act - executamos o método int resultado = calculadora.somar(a, b); // Assert - validamos o resultado esperado assertEquals(8, resultado); } }

Teste de unidade focado em validar a lógica interna do método somar()

Testes Paramétricos com @CsvSource

Executando o mesmo teste com múltiplos conjuntos de dados

@ParameterizedTest @CsvSource({ "2, 3, 5", "10, 20, 30", "-5, 5, 0", "0, 0, 0", "100, 200, 300" }) void testarSomaComMultiplosValores(int a, int b, int esperado) { // Arrange // Act int resultado = calculadora.somar(a, b); // Assert - valida para cada conjunto de parâmetros assertEquals(esperado, resultado); }
Vantagem: Um único método de teste valida múltiplos cenários, aumentando a cobertura de testes.

@CsvSource - Casos Mais Complexos

Testando validações e regras de negócio

@ParameterizedTest @CsvSource({ "usuario@email.com, Senha123!, true", "email-invalido, Senha123!, false", "usuario@email.com, 123, false", ", Senha123!, false", "usuario@email.com, , false" }) void testarValidacaoUsuario( String email, String senha, boolean esperado) { // Act boolean valido = validador.validarUsuario(email, senha); // Assert assertEquals(esperado, valido); }

Teste de caixa branca: conhecemos a lógica de validação interna

Teste Caixa Preta (Black-Box)

Definição

O teste de Caixa Preta valida o comportamento externo do sistema sem conhecer a implementação interna. Foca nos requisitos funcionais.

Objetivos

  • Validar funcionalidades do ponto de vista do usuário
  • Testar entradas e saídas esperadas
  • Verificar conformidade com requisitos
  • Testes funcionais, de sistema e aceitação
Não "enxergamos" o código

Apenas entradas e saídas são observadas

Exemplo: Teste Funcional

Validando o comportamento sem conhecer a implementação

Perspectiva do Usuário
  1. Usuário insere credenciais
  2. Clica em "Entrar"
  3. Espera ser redirecionado para dashboard
Foco: O sistema funciona conforme esperado?
Critérios de Aceite
  • Login válido → Dashboard
  • Login inválido → Mensagem de erro
  • Campos vazios → Validação

Testes End-to-End (E2E)

Testes de caixa preta que simulam o fluxo completo do usuário

Características

  • Testam o sistema completo
  • Simulam cenários reais de uso
  • Validam integração entre componentes
  • Não requerem conhecimento do código

Ferramentas Comuns

  • Selenium
  • Cypress
  • Playwright
  • TestCafe

Exemplo: E2E com Selenium

Automatizando o fluxo de login

@SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT) @ExtendWith(SeleniumExtension.class) public class LoginE2ETest { @Autowired private WebDriver webDriver; @Test void testarFluxoLoginCompleto() { // Acessa a página de login webDriver.get("/login"); // Preenche o formulário (caixa preta - não sabemos a implementação) webDriver.findElement(By.id("email")).sendKeys("user@email.com"); webDriver.findElement(By.id("senha")).sendKeys("Senha123!"); webDriver.findElement(By.id("btn-login")).click(); // Valida redirecionamento assertTrue(webDriver.getCurrentUrl().contains("/dashboard")); } }

Diagrama UML de Sequência

Visualizando o fluxo de interações entre componentes

O que é?

Diagrama que mostra como objetos interagem ao longo do tempo, representando a sequência de mensagens trocadas entre eles.

Importância para Testes

  • Entende o fluxo completo do sistema
  • Identifica pontos de teste
  • Documenta comportamento esperado
  • Facilita comunicação da equipe

Pirâmide de Testes

Equilíbrio entre diferentes tipos de teste

E2E / Caixa Preta
(Menos quantidade)
Integração
(Quantidade média)
Unidade / Caixa Branca
(Maior quantidade)

Princípios

  • Base larga: muitos testes de unidade (rápidos, baratos)
  • Meio: testes de integração (validam comunicação)
  • Topo: poucos testes E2E (lentos, caros)
  • Equilíbrio é essencial para qualidade

Melhores Práticas

Caixa Branca

  • Use @ParameterizedTest para cobrir casos variados
  • Mantenha testes independentes e isolados
  • Nomeie testes de forma descritiva
  • Teste caminhos felizes e exceções
  • Busque alta cobertura de código

Caixa Preta

  • Baseie testes em requisitos funcionais
  • Simule cenários reais de usuário
  • Automatize fluxos críticos E2E
  • Valide mensagens e feedbacks ao usuário
  • Teste em ambientes similares à produção

Resumo da Aula

Caixa Branca

Testa a estrutura interna do código. Usa @CsvSource para testes paramétricos. Foco em unidade e integração.

Caixa Preta

Testa comportamento externo. Usa Selenium/Cypress para E2E. Foco em sistema e aceitação.

Equilíbrio

Ambas abordagens são complementares. Use a pirâmide de testes como guia.
