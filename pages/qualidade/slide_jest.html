Retomada: onde o Jest entra

O que já vimos

  • Testes pequenos, previsíveis e focados
  • describe, test e expect
  • Cobertura com jest --coverage
  • Falha como feedback rápido para o desenvolvedor

O novo foco

  • Rodar automaticamente em push e pull_request
  • Gerar relatórios e artifacts no pipeline
  • Levar cobertura para o SonarCloud
  • Transformar teste em regra de merge do repositório
O teste continua o mesmo; o que muda é o contexto operacional: agora ele protege o repositório inteiro.

Fluxo mental da pipeline

push / pull_request -> actions/checkout -> setup-node -> npm ci -> npm test -- --ci --coverage -> coverage/lcov.info -> SonarCloud Code Analysis -> status check no Pull Request
Jest
Confirma comportamento e gera cobertura.
Actions
Executa tudo em ambiente previsível.
SonarCloud
Analisa smells, duplicação e hotspots.
Branch Rule
Conecta o resultado ao merge.

Workflow base: Node.js + Jest + cobertura

name: quality-ci on: push: branches: [main] pull_request: jobs: test: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: node-version: 20 cache: npm - run: npm ci - run: npm test -- --ci --coverage - uses: actions/upload-artifact@v4 if: always() with: name: coverage-report path: coverage/
checkout: baixa o código do commit do PR.
setup-node: fixa uma versão do Node para todos.
npm ci: instala exatamente o lockfile.
jest --ci --coverage: roda sem watch mode e produz lcov.info.
upload-artifact: deixa o relatório disponível para inspeção.

Conectando cobertura ao Sonar

sonar.projectKey=minha-org_meu-projeto sonar.organization=minha-org sonar.sources=src sonar.tests=tests sonar.test.inclusions=**/*.test.js sonar.javascript.lcov.reportPaths=coverage/lcov.info sonar.exclusions=node_modules/**,coverage/**

lcov.info

É o elo entre Jest e SonarCloud. Sem esse arquivo, a cobertura não aparece no dashboard.

sonar.sources

Define o código produtivo que será analisado por smells, bugs e duplicação.

sonar.tests

Separa o código de teste para evitar leitura incorreta das métricas.

SonarQube funciona com repositórios abertos?

Ponto SonarQube SonarCloud
Hospedagem Você sobe servidor, banco e atualizações Serviço pronto, sem infra própria
Repo aberto Funciona, mas exige mais operação Fluxo mais natural para open source
Integração com GitHub Mais configuração manual Mais direta para PR decoration
Uso em aula Bom para mostrar self-hosted Melhor para laboratório rápido com repo público
Na disciplina, faz sentido falar em SonarQube como categoria e usar SonarCloud quando quisermos algo prático em repositórios abertos.

Quality Gate no Pull Request

✓ test / ubuntu-latest ✓ coverage uploaded ✗ SonarCloud Code Analysis Quality Gate failed: - Coverage on new code < 80% - 2 new code smells - 1 duplicated block
1. O aluno abre um PR.
2. Actions roda Jest e publica artifacts.
3. SonarCloud analisa o código novo.
4. Se o quality gate falhar, o merge pode ficar bloqueado.
Teste responde “funciona?”. O quality gate amplia para “funciona com qualidade sustentável?”.

Resumo da Aula

Jest

Continua sendo a base do feedback funcional e da cobertura.

GitHub Actions

Tira o teste da máquina local e torna o resultado visível para o time.

SonarCloud

É o caminho mais direto para quality gate em repositórios públicos.

CI com Jest evita regressão. SonarCloud ajuda a evitar dívida técnica entrando pelo mesmo PR.
