Recap — O que já sabemos sobre Jest

Estrutura de um teste
describe('soma', () => {
  test('retorna 3', () => {
    expect(soma(1, 2)).toBe(3);
  });
});
Comandos básicos
npm test           # roda testes
npm test -- --watch  # modo watch
npm test -- --coverage
# relatório de cobertura
Matchers comuns
expect(x).toBe(3)
expect(x).toEqual({a:1})
expect(fn).toThrow()
expect(x).toBeTruthy()
expect(arr).toHaveLength(2)
Hoje o foco é: como tudo isso roda automaticamente no GitHub a cada push.

Jest Local vs Jest no CI — As Diferenças

Local (sua máquina)
  • Tem .env com variáveis configuradas
  • Banco de dados rodando localmente
  • Modo --watch é útil
  • Erros aparecem no terminal
  • Node.js já instalado
  • Pastas e arquivos já existem
CI (GitHub Actions)
  • Máquina virgem a cada execução
  • Sem .env — usa Secrets
  • --watch trava o processo — use --ci
  • Falha deve parar o merge
  • npm ci em vez de npm install
  • Precisa de --forceExit em alguns casos
Regra de ouro: "Se o teste só passa na minha máquina, ele não é um teste — é uma prece."

Estrutura de Projeto Pronta para CI

meu-projeto/ ├── .github/ │ └── workflows/ │ └── ci.yml ← pipeline ├── src/ │ └── soma.js ├── tests/ │ └── soma.test.js ├── jest.config.js ← config ├── package.json └── .gitignore ← sem node_modules

jest.config.js

/** @type {import('jest').Config} */
module.exports = {
  testEnvironment: 'node',
  collectCoverageFrom: ['src/**/*.js'],
  coverageThreshold: {
    global: {
      lines:      80,   // ← CI falha se < 80%
      functions:  80,
      branches:   70,
      statements: 80,
    }
  },
  coverageReporters: ['text', 'lcov', 'html'],
};
lcov gera o arquivo que o GitHub usa para exibir cobertura por linha.

package.json — Scripts para CI

{
  "name": "meu-projeto",
  "scripts": {
    "test":     "jest",
    "test:ci":  "jest --ci --forceExit",
    "coverage": "jest --coverage",
    "coverage:ci": "jest --ci --coverage --forceExit"
  },
  "devDependencies": {
    "jest": "^29.0.0"
  }
}

--ci

Desativa o modo interativo, trata snapshot desatualizado como falha. Ideal para pipelines.

--forceExit

Força o Jest a encerrar após os testes. Evita que conexões abertas (banco, servidor) travem o CI.

npm ci vs npm install

npm ci instala exatamente o que está no package-lock.json — reproduzível e mais rápido.

Workflow YAML — .github/workflows/ci.yml

name: CI — Jest

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout do código
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - name: Instalar dependências
        run: npm ci

      - name: Rodar testes com coverage
        run: npm run coverage:ci
1
on: dispara no push para main/develop e em todo Pull Request
2
checkout@v4 clona o repositório na máquina do CI
3
setup-node@v4 instala Node 20 e ativa cache do npm para acelerar
4
npm ci instala dependências de forma reproduzível
5
npm run coverage:ci roda Jest com --ci --coverage --forceExit

Artifacts — Salvando o Relatório de Cobertura

Adicione ao final do workflow:

      - name: Rodar testes com coverage
        run: npm run coverage:ci

      - name: Salvar relatório de cobertura
        uses: actions/upload-artifact@v4
        if: always()   # salva mesmo se testes falharem
        with:
          name: coverage-report
          path: coverage/
          retention-days: 7
O relatório HTML fica disponível para download na aba Actions do GitHub por 7 dias.

O que é gerado em coverage/:

coverage/ ├── lcov.info ← para badges ├── lcov-report/ │ ├── index.html ← relatório visual │ └── src/ │ └── soma.js.html ← linha a linha └── coverage-summary.json
O HTML mostra quais linhas do código nunca foram executadas pelos testes — em vermelho.

Coverage Threshold — CI Falha se Cobrir Pouco

// jest.config.js
coverageThreshold: {
  global: {
    lines:      80,
    functions:  80,
    branches:   70,
    statements: 80,
  },
  // Exigir 100% em arquivo crítico
  './src/auth.js': {
    lines:     100,
    functions: 100,
  }
}

Saída no CI quando a cobertura cai:

PASS tests/soma.test.js FAIL Jest: "global" coverage threshold for lines (80%) not met: 62% ● Coverage for lines (62%) does not meet global threshold (80%)
≥ 80%

CI passa ✓

< 80%

CI falha ✗

Comece com 60%, aumente gradualmente. Impor 100% logo cria testes vazios só para passar.

Matrix Strategy — Testar em Múltiplos Ambientes

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest]
        node: ['18', '20', '22']
      fail-fast: false  # continua mesmo com falha

    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
          cache: 'npm'
      - run: npm ci
      - run: npm run test:ci

O que o GitHub executa:

OSNode 18Node 20Node 22
Ubuntu ✓ pass ✓ pass ✓ pass
Windows ✓ pass ✗ fail ✓ pass
6 jobs em paralelo — descobre problemas específicos de SO ou versão do Node.

Branch Protection — CI como Porteiro

Configurar no GitHub:

1
Settings → Branches → Add rule
2
Branch name: main
3
☑ Require status checks to pass
4
Buscar e selecionar: test (ubuntu-latest)
5
☑ Require branches to be up to date
A partir de agora: merge bloqueado se o CI falhar.

O que o PR fica parecendo:

✗ CI — Jest / test (ubuntu-latest) — failing Required status check ✓ CI — Jest / test (windows-latest) — passing ⚠ Merging is blocked The required status check "test (ubuntu-latest)" is not passing because no recent commits match the required pattern, or they failed. [Merge pull request] ← botão desabilitado

Falha de teste:

FAIL tests/soma.test.js soma ✕ retorna 3 (4ms) ● soma › retorna 3 expect(received).toBe(expected) Expected: 3 Received: 2 3 | test('retorna 3', () => { > 4 | expect(soma(1, 2)).toBe(3); 5 | });

Falha de threshold:

FAIL Jest: "global" coverage threshold for branches (70%) not met: 45%

Dependência não instalada:

Error: Cannot find module 'dotenv' Require stack: - /home/runner/work/src/config.js → Solução: adicionar ao package.json e commitar o package-lock.json

Secrets — Variáveis de Ambiente no CI

1. Cadastrar no GitHub:

1
Settings → Secrets and variables → Actions
2
New repository secret → DB_URL
3
Valor: postgres://user:pass@host/db

2. Usar no workflow:

      - name: Rodar testes
        run: npm run test:ci
        env:
          DB_URL: ${{ secrets.DB_URL }}
          NODE_ENV: test

3. Acessar no código:

// src/db.js
const url = process.env.DB_URL;

// tests/db.test.js
beforeAll(async () => {
  await db.connect(process.env.DB_URL);
});

afterAll(async () => {
  await db.disconnect();
});
Nunca commite .env no repositório. Use Secrets no GitHub e .env.example para documentar.

Boas Práticas — Jest no CI

Faça isso
  • Use npm ci no pipeline
  • Sempre use --ci flag no Jest
  • Cache do node_modules via cache: 'npm'
  • Salve artifacts mesmo em falha (if: always())
  • Defina thresholds realistas e aumente gradualmente
  • Testes independentes — sem dependência de ordem
  • Use afterAll para fechar conexões
Não faça isso
  • Não use --watch no CI (trava infinito)
  • Não commite node_modules/
  • Não dependa de arquivos locais que não estão no repo
  • Não escreva testes que dependem de fuso horário local
  • Não ignore falhas com test.skip sem comentário
  • Não use --coverage no watch (lento demais)
  • Não commite credenciais — use Secrets

Workflow Completo — Tudo junto

name: CI — Jest + Coverage

on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'

      - run: npm ci

      - name: Rodar Jest com coverage
        run: npm run coverage:ci
        env:
          NODE_ENV: test
      - name: Salvar relatório
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: coverage-report
          path: coverage/
          retention-days: 7

      - name: Comentar cobertura no PR
        uses: ArtiomTr/jest-coverage-report-action@v2
        if: github.event_name == 'pull_request'
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
          coverage-file: coverage/report.json
          base-coverage-file: coverage/report.json
A action jest-coverage-report-action posta um comentário automático no PR mostrando o diff de cobertura.

6

7

8

9
