VCR em Java: WireMock

Stub programático (JUnit 5)
import com.github.tomakehurst.wiremock.junit5.*; import static com.github.tomakehurst.wiremock.client.WireMock.*; @WireMockTest(httpPort = 8089) class WeatherClientTest { @Test void retornaTemperatura() throws Exception { // "cassete" programático stubFor(get("/current?city=SP") .willReturn(okJson( "{\"temp\":28,\"desc\":\"Ensolarado\"}" ))); WeatherClient client = new WeatherClient("http://localhost:8089"); WeatherData data = client.fetchWeather("SP"); assertEquals(28, data.getTemp()); } }
Stub declarativo (arquivo JSON)
// src/test/resources/mappings/weather-sp.json { "request": { "method": "GET", "url": "/current?city=SP" }, "response": { "status": 200, "headers": { "Content-Type": "application/json" }, "bodyFileName": "weather-sp-response.json" } } // WireMock carrega o arquivo automaticamente // no @WireMockTest — funciona como "replay"
WireMock é o padrão de mercado para Java. Dependency: com.github.tomakehurst:wiremock-jre8:3.x (ou wiremock no Java 11+).

Sanitização do cassete — nunca vaze secrets

Mapping perigoso (NUNCA commitar)
// mappings/get-user.json — PERIGO { "request": { "method": "GET", "url": "/api/users/1", "headers": { "Authorization": { "equalTo": "Bearer sk-prod-SECRET123" } } }, "response": { "status": 200 } }
Mapping seguro (regex/placeholder)
// mappings/get-user.json — SEGURO { "request": { "method": "GET", "url": "/api/users/1", "headers": { "Authorization": { "matches": "Bearer .*" } } }, "response": { "status": 200 } } // Token real nunca gravado
Adicione src/test/resources/mappings/ ao .gitignore enquanto gravar responses reais. Mappings SÃO fixtures — trate como código.

O que é TestContainers?

Em vez de simular o banco, você roda um banco real em Docker — e o destrói ao final do teste.

1. Teste inicia — Jest/Vitest começa a rodar
2. TestContainers faz docker pull — baixa imagem se necessário
3. Container sobe — Postgres, Redis, MongoDB real
4. Testes rodam — contra o serviço real na porta aleatória
5. Container é destruído — sem rastros, sem estado residual
Diferente de mock, o TestContainers valida o comportamento real do driver, migrations e queries — não apenas que você chamou a função certa.

TestContainers em Java

Setup com JUnit 5 + @Testcontainers
import org.testcontainers.containers.PostgreSQLContainer; import org.testcontainers.junit.jupiter.*; import java.sql.*; @Testcontainers class UserRepositoryTest { @Container static PostgreSQLContainer<?> db = new PostgreSQLContainer<>("postgres:16") .withDatabaseName("testdb") .withUsername("test") .withPassword("test"); @BeforeAll static void setUp() { // roda Flyway/Liquibase runMigrations(db.getJdbcUrl(), db.getUsername(), db.getPassword()); } }
Teste usando o banco real
@Test void salvaEBuscaUsuario() throws Exception { UserRepository repo = new UserRepository(db.getJdbcUrl(), db.getUsername(), db.getPassword()); repo.save(new User("Ana", "ana@ex.com")); User found = repo.findByEmail("ana@ex.com"); assertEquals("Ana", found.getName()); } // Container sobe 1x por classe (static) // e é destruído pelo JUnit ao final
Maven: org.testcontainers:postgresql:1.20.x + org.testcontainers:junit-jupiter:1.20.x. Docker obrigatório no CI.

Quando usar VCR e quando usar TestContainers?

Critério VCR / HTTP Mock TestContainers
Alvo do teste APIs HTTP externas (REST, GraphQL) Bancos, filas, cache (Postgres, Redis, Kafka…)
Velocidade Muito rápido — sem Docker Mais lento — pull + start
Fidelidade Alta para payload HTTP; baixa para lógica do serviço Alta — serviço real
Requer Docker Não Sim
Ideal para Testes de unidade/integração de chamadas HTTP Testes de integração com persistência
Manutenção Re-gravar cassete ao mudar o contrato Baixa — imagem oficial sempre fiel
Na prática, use VCR/msw para testes de unidade rápidos e TestContainers para a suite de integração que valida o comportamento completo.

Pipeline de qualidade completa

## .github/workflows/quality.yml jobs: unit: # rápido — sem Docker runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-java@v4 with: { java-version: '21', distribution: temurin, cache: maven } - run: mvn test -Dtest="**/*UnitTest" # WireMock intercepta HTTP — sem rede real integration: # mais lento — com Docker runs-on: ubuntu-latest # ubuntu-latest já tem Docker steps: - uses: actions/checkout@v4 - uses: actions/setup-java@v4 with: { java-version: '21', distribution: temurin, cache: maven } - run: mvn test -Dtest="**/*IntegrationTest" # @Testcontainers sobe Postgres/Redis via Docker sonar: needs: [unit, integration] steps: - uses: SonarSource/sonarcloud-github-action@v2
unit — roda em <30s, bloqueia PR rápido
integration — valida comportamento real com dados reais
sonar — quality gate só abre quando ambos passam

Anti-patterns para evitar

Cassete com secret

Nunca comitar arquivo de cassete que contém token, senha ou chave de API. Use a etapa de sanitização obrigatoriamente.

Cassete eterno

Se a API mudou o contrato e você não regravou, o teste passa localmente mas falha em produção. Agende re-gravação periódica.

TestContainer em teste de unidade

Container em teste de unidade é lento demais. Reserve-o para a suite de integração.

Container compartilhado entre testes

Estado residual entre testes causa flakiness. Use beforeEach para limpar tabelas ou suba container por suite.

Regra de ouro: "testes não devem depender de ordem de execução nem de estado externo persistente."

Resumo da Aula

VCR

Grava chamadas HTTP reais e reproduz offline. Testes rápidos e determinísticos.

Secrets

.env local → CI Secrets → Vault em prod. Sanitize cassetes antes de commitar.

TestContainers

Sobe serviço real em Docker por suite. Alta fidelidade sem infraestrutura permanente.

VCR resolve a instabilidade de rede; TestContainers resolve a fidelidade do serviço; secrets bem guardados resolvem a segurança. Os três juntos formam uma suite de integração profissional.
