Qualidade de Software

Aula 07 - Jest no GitHub Actions + SonarCloud

Esta aula retoma os testes com Jest, mas desloca o foco para integração contínua no GitHub Actions e para a análise de qualidade em repositórios públicos.

A ideia central é simples: o teste continua importante, mas agora ele vira parte de uma política de merge e de um fluxo de observabilidade do código.

1. O papel de cada ferramenta

  • Jest: valida comportamento e gera cobertura.
  • GitHub Actions: executa tudo automaticamente em push e pull request.
  • SonarCloud: lê o código e a cobertura para apontar smells, bugs potenciais, duplicação e quality gate.
Quando falamos “SonarQube” em aula, vale diferenciar: para repositórios públicos, a forma mais prática costuma ser o SonarCloud, que evita instalar e manter servidor.

2. Workflow mínimo no GitHub Actions

name: quality-ci

on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
      - run: npm ci
      - run: npm test -- --ci --coverage

3. Integração com SonarCloud

Para que a cobertura apareça no dashboard, o Jest precisa gerar coverage/lcov.info. Esse arquivo é apontado em sonar-project.properties.

sonar.projectKey=minha-org_meu-projeto
sonar.organization=minha-org
sonar.sources=src
sonar.tests=tests
sonar.test.inclusions=**/*.test.js
sonar.javascript.lcov.reportPaths=coverage/lcov.info

4. O que observar no pull request

  • Se os testes passaram.
  • Se a cobertura do código novo caiu.
  • Se apareceram smells, duplicação ou security hotspots.
  • Se o quality gate ficou verde antes do merge.

5. Exercícios de fixação

  1. Explique a diferença entre validar comportamento com Jest e avaliar qualidade estrutural com SonarCloud.
  2. Monte um workflow mínimo para um projeto Node.js público com testes e cobertura.
  3. Descreva por que npm ci é mais adequado que npm install em CI.
  4. Liste três motivos para usar SonarCloud em um repositório público em vez de subir um SonarQube próprio em uma aula prática.
  5. Defina um quality gate simples para novo código e justifique os critérios escolhidos.
