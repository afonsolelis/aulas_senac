CI é integração frequente + feedback automático

A ferramenta executa; a equipe pratica.

Pequenos lotes

Mudanças curtas são mais fáceis de revisar, testar e reverter.

Branch saudável

Main permanece executável; vermelho é tratado imediatamente.

Mesmo contrato

Local e CI usam a mesma versão de Java e o mesmo comando Maven.

Não é CI: acumular uma semana de trabalho numa branch e apertar “Run workflow” antes da entrega.

Anatomia de um workflow

Evento

push, pull_request ou manual.

Workflow

Arquivo YAML em .github/workflows.

Job

Unidade executada em um runner limpo.

Step

Action reutilizável ou comando de shell.

Estado não é compartilhado entre jobs. Para transportar relatório, publique artifact; para ordenar, use dependências.

Pipeline mínimo do Foot Fanatics

name: qualidade
on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - uses: actions/setup-java@v5
        with:
          distribution: temurin
          java-version: '21'
          cache: maven
      - run: ./mvnw -B verify

Use versões estáveis das actions e Java igual ao projeto. -B evita interação; verify percorre o ciclo até as verificações.

Por que verify?

test

Compila e executa testes unitários do Surefire.

integration-test

Pode iniciar ambiente e executar testes do Failsafe.

verify

Também aplica checks e gates ligados às fases posteriores.

O comando local documentado deve ser o comando da CI. “Na minha máquina passa” perde força quando a execução é equivalente.

Feedback rápido, sem atalhos

Acelere com segurança
  • Cache de dependências pelo pom.xml
  • Cancelamento de execução obsoleta
  • Jobs independentes em paralelo
  • Testes determinísticos
Não esconda custo
  • Pular testes lentos sem estratégia
  • Reutilizar workspace sujo
  • Usar continue-on-error no gate
  • Rerun até “dar verde”
concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }

Falhou? Preserve evidência

- name: Publicar relatórios de teste
  if: always()
  uses: actions/upload-artifact@v4
  with:
    name: relatorios-${{ github.run_number }}
    path: |
      target/surefire-reports/
      target/failsafe-reports/
    if-no-files-found: warn
    retention-days: 7

always() publica a evidência mesmo com teste vermelho. Artifact não corrige diagnóstico ruim, mas preserva XML, stack trace e contexto daquela execução.

Segurança por padrão

Segredos

Nunca no YAML, log, artifact ou fork não confiável.

Permissões

contents: read; conceda escrita somente ao job que precisa.

Dependências

Actions estáveis, revisadas e atualizadas conscientemente.

Evite pull_request_target para executar código de contribuição com segredos. O contexto privilegiado muda o modelo de ameaça.

O check vira política

  1. Abrir pull request para main.
  2. Exigir o check qualidade / test.
  3. Exigir branch atualizada e revisão por par.
  4. Bloquear merge enquanto houver falha.
  5. Investigar o vermelho; não contornar o gate.
Contrato social

Main verde pertence a todos. A prioridade ao quebrar é recuperar o fluxo, com reversão ou correção pequena.

Prática: primeiro gate do Foot Fanatics

  1. Criar .github/workflows/quality.yml para PR e push em main.
  2. Configurar checkout, Java 21, cache Maven e ./mvnw -B verify.
  3. Publicar relatórios com if: always() e retenção curta.
  4. Abrir PR, inserir falha proposital e capturar o check vermelho.
  5. Corrigir, obter verde e configurar proteção da branch.
Entregável da Aula 06

CI como evidência

Precisa existir
  • Workflow versionado
  • Java 21 + Maven cache
  • Relatórios como artifact
  • Check obrigatório no PR
Evidências
  • Uma execução vermelha intencional
  • Correção seguida de verde
  • Link/ID do run no RTM/README
  • Nenhum segredo em log

Síntese

CI é hábito: integração frequente e pequenos lotes.
Workflow é código: versionado, revisado e testado.
Vermelho é informação: preserve evidência e trate rápido.
Gate é política: qualidade antes do merge.

Depois da prova: aprofundar JUnit e tornar cobertura/análise estática parte do gate.
