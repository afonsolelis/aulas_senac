Objetivo: proteger E2 — Sessão & Acesso

Tempo

Token expira exatamente no limite definido.

Ramos

Ausente, inválido, expirado, revogado e válido.

Gate

Nenhuma mudança entra sem testes e análise.

Resultado: cobertura explica o que foi executado; o teste explica se o comportamento está certo.

JUnit Jupiter: linguagem de teste

Estrutura
  • @Test define caso
  • @BeforeEach recria contexto
  • @Nested organiza cenários
  • @DisplayName comunica intenção
Oráculos
  • assertEquals compara valor
  • assertThrows observa falha
  • assertAll agrupa propriedades
  • assertTimeout limita execução
Lifecycle não é depósito de dados invisíveis. Setup grande e compartilhado esconde o motivo do cenário.

Organize por comportamento

@Nested
@DisplayName("token expirado")
class TokenExpirado {
  @Test
  void negaAcessoMesmoComAssinaturaAtiva() {
    var agora = Instant.parse("2026-09-21T10:00:00Z");
    var token = tokenComExpiracao(agora.minusSeconds(1));

    var decisao = autorizador.avaliar(token, assinaturaAtiva(), agora);

    assertEquals(MotivoNegacao.TOKEN_EXPIRADO, decisao.motivo());
  }
}

O nome da classe dá contexto; o método revela a regra; o tempo é dado de entrada, não ambiente.

Parametrize classes de equivalência e limites

@ParameterizedTest(name = "expira em {0}s → válido? {1}")
@CsvSource({
  "-1, false",
  " 0, false",
  " 1, true"
})
void respeitaLimiteDeExpiracao(long deslocamento, boolean esperado) {
  var agora = Instant.parse("2026-09-21T10:00:00Z");
  var token = tokenComExpiracao(agora.plusSeconds(deslocamento));

  assertEquals(esperado, validador.estaValido(token, agora));
}
Trinca de limite: imediatamente antes, exatamente no limite e imediatamente depois.

Tempo é uma dependência

Frágil
Instant.now(); Thread.sleep(1000);

Pode falhar por carga, fuso ou instante de execução.

Determinístico
Clock.fixed(instante, ZoneOffset.UTC)

Produção usa relógio do sistema; teste injeta relógio controlado.

No Foot Fanatics, tempo decide segurança. Se o teste não controla o relógio, ele não controla o cenário.

Cobertura responde “executou?”

Ela não responde “testou certo?”.

Linha

Percentual de linhas executáveis alcançadas.

Branch

Resultados verdadeiro/falso das decisões alcançados.

Complexidade

Sinal de caminhos independentes e custo de teste.

100% de linha pode deixar o ramo “token expirado” sem verificação. Cobertura guia perguntas; não certifica correção.

JaCoCo: medir e falhar o build

<plugin>
  <groupId>org.jacoco</groupId>
  <artifactId>jacoco-maven-plugin</artifactId>
  <version>0.8.15</version>
  <executions>
    <execution>
      <goals>
        <goal>prepare-agent</goal>
      </goals>
    </execution>
    <execution>
      <id>report-and-check</id>
      <phase>verify</phase>
      <goals>
        <goal>report</goal>
        <goal>check</goal>
      </goals>
    </execution>
  </executions>
</plugin>
Metas do projeto

80% linhas

70% branches

Configure regras no elemento BUNDLE e rode ./mvnw verify. Versão estável do semestre: 0.8.15.

Leia o relatório, não só o total

Vermelho

Instrução não executada. Pergunte se representa risco ou código morto.

Amarelo

Decisão parcialmente coberta. Falta pelo menos um resultado.

Verde

Executado, mas ainda precisa de assert relevante.

target/site/jacoco/index.html

Priorize autorização, expiração e transições; não escreva teste trivial só para pintar DTO de verde.

SonarCloud acrescenta outra lente

Bugs

Padrões propensos a comportamento incorreto.

Vulnerabilidades

Riscos de segurança analisáveis.

Manutenibilidade

Dívida e complexidade que encarecem mudança.

Duplicação

Código repetido e chance de correção divergente.

Análise estática encontra padrões, não comprova regra de negócio. SonarCloud e testes são complementares.

Análise na CI e Quality Gate

- uses: actions/checkout@v6
  with:
    fetch-depth: 0
- uses: actions/setup-java@v5
  with:
    distribution: temurin
    java-version: '21'
    cache: maven
- name: Testar e analisar
  env:
    SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
  run: ./mvnw -B verify \
       org.sonarsource.scanner.maven:sonar-maven-plugin:sonar

Configure sonar.organization e sonar.projectKey; escolha análise pela CI no onboarding para não duplicar análise automática. Proteja o token.

Prática: blindar sessão e acesso

  1. Implementar ValidadorToken com Clock injetável.
  2. Cobrir ausente, inválido, expirado, revogado e válido; parametrizar o limite temporal.
  3. Configurar JaCoCo com relatório e gates de 80% linhas / 70% branches.
  4. Abrir o HTML e eliminar lacunas de risco — não lacunas cosméticas.
  5. Importar no SonarCloud, configurar token e análise via CI.
  6. Abrir PR e corrigir o novo código até o Quality Gate passar.
Entregável da Aula 07

E2 protegido por três evidências

JUnit

Cenários legíveis, limite temporal e relógio determinístico.

JaCoCo

Relatório HTML/XML e build falhando abaixo de 80/70.

SonarCloud

Análise no PR e Quality Gate aprovado no novo código.

Atualize RTM: RF-E2 → riscos → testes → relatório JaCoCo → análise do PR.

Síntese

JUnit expressa comportamentos e limites.
Clock torna tempo testável e determinístico.
JaCoCo revela caminhos executados.
SonarCloud avalia riscos estáticos e novo código.

Qualidade não é um número: é uma decisão sustentada por evidências diferentes.
