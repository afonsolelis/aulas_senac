Agenda da prática

Sair da aula com o projeto entregue: aplicação reproduzível a partir do README, tag do release candidate com CI verde, pacote de evidências indexado e decisão de qualidade assinada pelo grupo.

19h10–20h50

  1. Abertura e combinados (10 min)
  2. Prompt 1 · checklist e clone limpo (50 min)
  3. Correções de bloqueadores (40 min)

21h05–22h45

  1. Prompt 2 · release candidate (40 min)
  2. Prompt 3 · decisão e envio (40 min)
  3. Checagem na mesa (20 min)

Antes de abrir o agente

Pré-requisitos

  • Relatório de qualidade da Aula 13 versionado.
  • Repositório público no GitHub.
  • Nomes completos dos integrantes, até quatro por grupo.

Uso do agente

  • Trabalhe numa branch da prática, nunca direto na main.
  • Leia o diff inteiro antes de aceitar a mudança proposta pelo agente.
  • Rode ./mvnw -B verify antes de cada commit e abra pull request no fim.
  • Não cole token, senha nem dado pessoal real no prompt.
Os prompts estão no material escrito, prontos para copiar. O projeto é o de cada equipe, o sistema de Organização de Recursos.
Prompt 1 de 350 min

Checklist da entrega em clone limpo

Atue como avaliador externo do sistema de Organização de Recursos. Você pode usar o terminal (bash) e o git. Clone o repositório num diretório temporário, sem reaproveitar nada da máquina de quem desenvolveu, e siga apenas o README para subir a aplicação e rodar ./mvnw -B verify. Anote cada passo que faltou ou falhou. Depois confira os entregáveis da especificação: repositório com revisão por pares, aplicação executável, README e documentação da API, docs/rtm.md, diagramas de contexto, componentes e sequências críticas, plano e relatório de testes, pipeline de CI, relatórios do SonarCloud e do JaCoCo, plano e resultado do teste de carga, registro de defeitos e relatório final de qualidade. Escreva docs/entrega/checklist.md com item → existe → atualizado → caminho, e liste os bloqueadores em ordem. Não corrija nada nesta etapa.

Antes de aceitar: O clone foi feito do zero; cada item do checklist tem caminho.
Prompt 2 de 340 min

Release candidate e pacote de evidências

Atue como responsável pelo release. Você pode usar o terminal (bash), o git e o gh. Depois que os bloqueadores do checklist estiverem corrigidos e o CI estiver verde na main, crie a tag anotada v1.0.0-rc1 no commit avaliado e envie a tag. Escreva CHANGELOG.md com o que entra nesta versão. Monte docs/evidencias/README.md como índice do pacote: link da execução do CI no commit da tag, relatório do JaCoCo como artifact, link do Quality Gate do SonarCloud, docs/performance/resultado-01.md, docs/rtm.md, docs/defeitos/ e docs/relatorio-qualidade.md. Toda evidência deve apontar para o commit da tag. Se for preciso corrigir algo depois, crie v1.0.0-rc2; nunca mova uma tag já usada.

Antes de aceitar: A execução do CI citada é do commit da tag; nenhum link do índice está quebrado.
Prompt 3 de 340 min

Decisão de qualidade e envio

Atue como relator da decisão de qualidade. Você pode usar o terminal (bash) para ler o pacote de evidências. Escreva docs/decisao-qualidade.md com a decisão (liberar, liberar com ressalvas ou bloquear), os critérios usados, a evidência de cada critério, os riscos aceitos com impacto, justificativa e responsável, e o nome de cada integrante declarando o que fez. A decisão deve ser proporcional à evidência: não escreva pronto para produção a partir de testes locais. Ao final, gere um texto curto com o link do repositório público e a tag avaliada, para um integrante colar no formulário de entrega do Hub.

Antes de aceitar: Os riscos aceitos têm responsável; um único integrante envia pelo grupo.
Entregável da Aula 14

Tag v1.0.0-rc1 com CI verde, docs/entrega/checklist.md, docs/evidencias/README.md, docs/decisao-qualidade.md e o envio feito no formulário de entrega.

O que confiro na mesa

  • Clono o repositório e sigo o README.
  • Abro a execução do CI ligada à tag.
  • Confiro se o formulário recebeu a entrega do grupo.
