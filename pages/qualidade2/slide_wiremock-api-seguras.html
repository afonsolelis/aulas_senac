O problema

Teste que depende da internet não é determinístico

Mudam a rede, os dados, o limite de requisições, a credencial e até o contrato.

IndisponibilidadeA suíte falha sem defeito no nosso código.
Dados mutáveisO placar esperado deixa de existir.
Segredo expostoToken real vaza em código ou log.
Regra: um teste automatizado deve controlar entrada, tempo e resposta.

A pirâmide saudável combina isolamento rápido com poucos testes reais de contrato.

WireMock

Arrange → Act → Assert, agora na fronteira HTTP

1. Stub

Defina método, caminho e resposta controlada.

2. Chamada

Aponte o cliente para a porta dinâmica do servidor simulado.

3. Verificação

Asserte a saída e verifique o request enviado.

stubFor(get(urlEqualTo("/matches/42"))
  .willReturn(okJson("{\"status\":\"FINISHED\"}")));

assertThat(client.buscarJogo(42).status()).isEqualTo("FINISHED");
verify(getRequestedFor(urlEqualTo("/matches/42")));
Falhar com segurança

A resposta externa nunca é confiável

TimeoutTempo finito de conexão e leitura.
ValidaçãoSchema, tipo e domínio antes de persistir.
Erro neutroNão devolver token, stack trace ou corpo externo.
SegredoVariável de ambiente; logs com mascaramento.
Retry só para operação idempotente, falha transitória e com limite. Repetir cegamente multiplica incidentes.

Contrato observável

2xxParsear e validar
4xxNão repetir; corrigir request/credencial
5xxFalha transitória; retry limitado
TimeoutFallback ou 503 próprio

O teste deve capturar:

  • método, URL, query e headers esperados;
  • status e schema mínimos;
  • comportamento para erro, atraso e corpo inválido;
  • ausência de segredo na resposta e nos logs.

Quando usar Testcontainers junto

PostgreSQL real

Valida mapeamento JPA, constraint, transação e migração no mesmo banco usado em produção.

@Container PostgreSQLContainer<?> db

WireMock HTTP

Controla respostas do provedor sem rede externa e sem credencial real.

@WireMockTest(httpPort = 0)
Um teste de integração pode exercitar a aplicação inteira: request → regra → banco real → HTTP simulado → resposta.
Prática · evidência da aula

Isole uma integração do Foot Fanatics

  1. Criar a porta SportsProvider e o adapter HTTP.
  2. Configurar URL e token fora do código; usar porta dinâmica no teste.
  3. Automatizar os cenários INT-01 a INT-05 com WireMock.
  4. Verificar método, caminho e headers sem registrar segredo.
  5. Rodar no pipeline e anexar resultado à RTM.
Entregável: suíte reproduzível, evidência do pipeline e linha da RTM ligando requisito → teste → execução.

Integração confiável é falha ensaiada

WireMock controla HTTP. Testcontainers aproxima a infraestrutura. A RTM prova o resultado.
